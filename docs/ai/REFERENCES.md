# AI Documentation References

Simple reference guide for consistent documentation paths.

## Standard Directory Structure

```
docs/
├── ai/
│   ├── prompts/       # AI agent prompts
│   └── templates/     # Template files
├── architecture/      # System architecture docs
├── development/       # Development context
├── features/          # Feature specifications
├── guidelines/        # Coding standards
└── plans/             # Implementation plans
```

## Common References

When writing AI prompts, use these standard paths:

### Templates
- Prompt template: `docs/ai/templates/prompt.md`
- Feature template: `docs/ai/templates/feature.md`
- Plan template: `docs/ai/templates/plan.md`

### Guidelines
- Go standards: `docs/guidelines/go-standards.md`
- Testing strategy: `docs/guidelines/testing-strategy.md`
- Interface patterns: `docs/guidelines/interface-pattern.md`

### Context Files
- Project context: `docs/development/project-context.md`
- Environment setup: `docs/development/environment.md`
- Core foundations: `docs/development/foundations.md`

## Best Practices

1. **Use direct paths** - Reference files directly with their full path
2. **Be consistent** - Use the same path format everywhere
3. **Keep it simple** - No complex variable substitution needed
4. **Trust Claude Code** - It understands file paths naturally

## Example Usage

```markdown
## WORKFLOW
1. Read feature document from `docs/features/`
2. Apply standard practices based on guidance from `docs/guidelines/`
3. Use template from `docs/ai/templates/plan.md`
4. Reference context in `docs/development/project-context.md`
```
