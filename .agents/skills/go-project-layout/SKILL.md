# Go Project Layout

The layout and its reasons are the accepted decision in
`docs/decisions.md`; `make architecture-check` enforces the import rules.
This skill is the procedure for placing a change.

## The shape

```
main.go, cmd/              Cobra commands; process wiring only
internal/
  api/v1/                  generated by ogen; never edited
  app/                     composition root: builds every concrete, owns the lifecycle
  auth/                    token validation and generation; imports nothing internal
  cli/                     signal-driven shutdown; cli/seed seeds development data
  controller/              the one implementation of the generated Handler: mapping only
  domain/                  business data, persistence inputs, business errors; a leaf
  modules/<capability>/    business capabilities (user, credential)
  platform/<service>/      technical infrastructure with no business meaning
  templateinit/            the initializer; make init deletes it
```

`api/`, `modules/` and `platform/` are grouping directories; Go files go in
their children. These top-level groups are the only ones `make
architecture-check` accepts; a new one is a change to the decision document
and the check together.

## Where does a new file go?

| The file is | It goes in |
|---|---|
| Config loading, env binding | `internal/platform/config/` |
| Pool, migrations, queries, the test harness | `internal/platform/database/...` |
| Metrics, tracing, logger setup | `internal/platform/observability/` |
| HTTP middleware / server and routing | `internal/platform/http/middleware/` / `server/` |
| A capability's model mapping, repository and business logic | `internal/modules/<capability>/` |
| A data type or error two capabilities share | `internal/domain/` |
| Mapping a generated request or response to a domain call | `internal/controller/` |
| Token handling | `internal/auth/` |
| Constructing and wiring concretes, start and stop | `internal/app/` |
| A command or development tooling (seed) | `cmd/` and `internal/cli/` |
| "Generic, used everywhere" | a `domain` type or a `platform` capability; never `utils`, `helpers`, `common` or `shared` |

## The rules `make architecture-check` enforces

1. `internal/platform/...` imports neither `internal/domain` nor
   `internal/modules`.
2. `internal/domain` imports no other internal package.
3. `internal/modules/...` never imports `internal/api`.
4. Only `app`, `auth`, `controller` and `platform/http/server` import
   `internal/api`.
5. Only `modules/user` and `platform/database/postgres` import the sqlc `db`
   package.
6. No package outside the accepted top-level groups; no grab-bag directory.

A violation is fixed by moving the type down (usually into `domain`) or by
adding a port, not by widening the check.

## The rules the check cannot see

- **Ports belong to the consumer.** `domain` holds no repository interface.
  A module or controller that needs another package's behaviour declares a
  small unexported interface for exactly the methods it calls; the concrete
  satisfies it structurally and is injected from `internal/app`.
- **Concretes are built only in `internal/app`** (or a command's own setup in
  `cmd/`). Business code never calls a pool, SDK or storage constructor.
- **The controller only maps.** Generated request to domain call to generated
  response; business decisions live in the module.
- **A module service exists only for orchestration** across several
  repositories or ports. A single-repository read stays a repository call.
- **Persistence types stay in the adapter.** Generated `db` rows and pgtype
  values are mapped to `domain` values inside the module.

## Add a business capability

1. Create `internal/modules/<capability>/` with a `doc.go` or package comment
   stating what it promises.
2. Put shared data types and business errors in `internal/domain/`.
3. Declare the ports it consumes as local interfaces.
4. Add its queries and repository per the `golang-database` skill.
5. Construct it in `internal/app` and inject it into the controller.
6. If it is exposed, change `api/openapi.yml` first, `make generate`, then map
   it in `internal/controller/`; see the `api-contract` skill.

## Plan and review checklist

Each item is a fail condition:

- [ ] Business code imports a concrete infrastructure type or SDK instead of
      a local port.
- [ ] A concrete is constructed outside `internal/app` or `cmd/`.
- [ ] The controller holds a business decision.
- [ ] A generated `db` or `api` type escapes its edge.
- [ ] A seam cannot be driven by a fake in a unit test.

## Verify

```bash
make architecture-check
make check
```
