# AGENTS.md

`go-starter` is a template for a production Go HTTP service: clone it, run
`make init` once to give it your module path and names, and build on it. It is
one binary (`main.go` and the Cobra commands in `cmd/`) whose packages live in
`internal/`: an OpenAPI-first API generated by ogen, PostgreSQL through pgx,
sqlc, squirrel and Goose, and Podman for local services and images. The design
is in `docs/`; start at `docs/README.md`.

## Scope and restraint

Make the smallest change that is correct, safe and verifiable, following the
local pattern. Don't refactor, rename, reformat, update dependencies, rewrite
tests or expand documentation unless the requested behaviour needs it. A
review reports concrete, evidenced defects, not style preferences or
speculative refactors.

## Documentation

`project-docs` is the standard (the document set, comments, the same-commit
rule); `sound-patterns` settles style (default to what the Go stdlib does,
measure).

- **Each document answers one question.** `docs/README.md` is the table of
  what answers what; this file is where the code is and what will bite you.
- **Documents name no Go symbol; code cites documents.** The reason goes in
  the comment as prose, then the pointer: `// See docs/<file>.md#<heading>`.
  Cite only product and design decisions, never local mechanics.
- **Headings are anchors.** Renaming one breaks its citations; fix them in the
  same commit. `make docs-check` verifies every citation resolves.
- **A change that moves a command, path, behaviour or decision updates the
  document in the same commit.**
- **Never reference a story, epic, backlog item or the plan** in a comment,
  document or test name. `make docs-check` fails on a work-item identifier.
- **Nothing in `docs/research/` is cited from code**, and it is never edited.

## Testing

- `make test` is the unit tier: `go test ./...` with no build tag and no
  external service. It stays cacheable; don't add `-count=1` to it.
- Tests that need PostgreSQL carry `//go:build integration` and use
  `internal/platform/database/postgrestest`: one Testcontainers PostgreSQL per
  test binary, a fresh database per test. `make test-integration` and
  `make cover` run them uncached.
- Fakes sit at the consumer-side interfaces the modules and the composition
  root depend on; prefer them to mocks of concrete types.
- The floor is what the gate enforces, not a target to write tests toward.

## Version control

- **Never `git add -A`, `git add .` or `git commit -a`.** Name the paths.
- Subject: `type(scope): subject` (conventional commits), imperative, lower
  case, under 72 characters. A subject that needs "and" is two commits.
- Keep generated output, dependency updates, format-only edits and behaviour
  changes in separate commits unless one change needs them together.
- Add a `CHANGELOG.md` entry when a change requires action from someone
  using the template.
- The push is the person's. Never push.

## Architecture

Package doc comments are the detailed map; the boundary rules and their
reasons are in `docs/decisions.md`.

```
main.go, cmd/            Cobra commands (serve, migrate, seed, version); process wiring only
internal/
  app/                   composition root: builds every dependency and owns the lifecycle
  domain/                business data, persistence inputs, business errors; imports nothing internal
  modules/               business capabilities (user, credential)
  controller/            maps generated transport to domain calls; no business logic
  auth/                  token validation and generation, the subject in the request context
  api/v1/                generated by ogen from api/openapi.yml; never edited
  platform/              technical infrastructure with no business meaning
    config/ health/ observability/ ratelimiter/ http/{server,middleware}/
    database/postgres/   pool, migrations/, queries/ (sqlc input), db/ (sqlc output)
    database/postgrestest/  integration-test harness
  cli/                   signal-driven shutdown for the commands; cli/seed seeds development data
  templateinit/          the initializer behind make init; deletes itself
tools/initialize/        the initializer's entrypoint; deleted by make init
web/                     embedded static files
api/openapi.yml          the HTTP API contract
```

Dependencies point down: `app` imports everything; `controller` imports the
generated transport, `auth` and `domain`; `modules` import `domain` and
selected `platform` packages; `platform` imports neither `domain` nor
`modules`; `domain` and `auth` import nothing internal.

Besides the stack named at the top: Chi routes, Viper layers configuration,
Zap logs, Prometheus and OpenTelemetry observe. Tool versions are pinned in `scripts/tool-versions.env`
(ogen in `go.mod`), the release in `.goreleaser.yaml`.

Skills for this layout: `go-project-layout` (where a package goes),
`api-contract` (changing the OpenAPI contract), `golang-database` (queries,
migrations, repositories), `podman-operations` (host setup, local services,
Testcontainers, images). The full list is `.agents/skills/README.md`.

## Invariants

- **Import direction holds.** The rules above are checked by
  `make architecture-check`; a change that needs to break one is a design
  change, not a fix.
- **Generated code is never edited.** `internal/api/v1/` comes from
  `api/openapi.yml` and `internal/platform/database/postgres/db/` from the SQL
  in the sibling queries and migrations directories; change the source and
  `make generate`. `make generate-check` fails on drift.
- **`api/openapi.yml` is the source of truth** for the HTTP API. Change it
  first, regenerate, then adapt `internal/controller/`.
- **Generated transport stays at the edge.** Only `app`, `auth`, `controller`
  and the HTTP server under `internal/platform/http/server/` may import
  `internal/api/`.
- **sqlc output has one owner.** Only `internal/modules/user/` and
  `internal/platform/database/postgres/` import the generated `db` package.
- **Migrations are append-only.** Never edit one that may have been applied;
  add a new one with `make migration`.
- **Concrete infrastructure is built in `internal/app/`** (or a command's own
  root) and injected; modules depend on small consumer-side interfaces.
- **No grab-bag packages.** No `utils`, `helpers`, `common` or `shared`
  package under `internal/`; name a package for what it owns.

## Gotchas

- **Integration tests pass but ran nothing.** Without a reachable container
  runtime `postgrestest` skips; set `GOSTARTER_REQUIRE_CONTAINERS=1` to make
  that fatal, as CI does.
- **Testcontainers cannot reach rootless Podman.** Start the user socket,
  point `DOCKER_HOST` at it and set `TESTCONTAINERS_RYUK_CONTAINER_PRIVILEGED=true`
  (the CI workflow shows the three lines).
- **A migration runs out of order.** Bare `goose create` writes a timestamped
  name that sorts after the sequential ones; always use `make migration`.
- **A setting in `.env` is ignored.** Only `make dev-run` loads `.env`; the
  binary reads no dotenv file, so export it before `go run .`. A variable is
  `GOSTARTER_` plus the key with dots and dashes as underscores
  (`GOSTARTER_RATE_LIMIT_MAX_KEYS`); a flag beats it.
- **`make init` says the clone is already initialized.** It deletes
  `tools/initialize` and `internal/templateinit` when it finishes, so it runs
  once per clone.
- **`podman compose` reports no compose provider.** Install `podman-compose`
  or a Compose v2 `docker-compose` binary. Port 5432 in use means another
  PostgreSQL is running; stop it or change both the Compose mapping and
  `GOSTARTER_DATABASE_URI`.
- **`make skills-check` fails on a vendored skill edited here.** Shared skills
  are edited in `../skills`, then `make skills-sync`.
